# 내엑셀 DLL 배포본 설치·실행 안내

XLAM을 여는 것만으로 DLL이 등록되지는 않습니다. 처음 한 번 아래 설치 절차를 진행하세요.

## 1. 준비

ZIP 전체를 Windows 로컬 폴더에 압축 해제합니다. `패키지` 안의 `deployment`, `payload`와 파일 구조를 유지하세요. 문서를 저장하고 Excel을 모두 종료합니다.

파일 탐색기에서 `패키지` 폴더를 연 다음 주소 표시줄에 `powershell`을 입력하고 Enter를 누릅니다. 아래 명령은 모두 그 폴더에서 실행합니다.

## 2. 확인 및 설치

한 줄씩 실행하고 오류가 나면 다음 단계로 넘어가지 마세요.

```powershell
powershell.exe -NoProfile -File ".\deployment\Verify-NxEnhancedPackage.ps1" -PackageRoot "."
powershell.exe -NoProfile -File ".\deployment\Install-NxEnhanced.ps1" -PackageRoot "." -ProbeOnly
powershell.exe -NoProfile -File ".\deployment\Install-NxEnhanced.ps1" -PackageRoot "." -OptIn -InstallXlamToXLStart
```

마지막 명령에서 `PASS|INSTALL`이 표시되면 설치가 완료됩니다. DLL은 사용자 로컬 폴더에 복사되고 COM 추가 기능으로 등록됩니다. XLAM은 Excel 시작 폴더에 배치됩니다. Windows 비트수가 아니라 설치된 Excel의 비트수를 확인하며, 현재 스크립트는 네이티브 ARM64/ARM64EC Excel을 지원하지 않습니다.

## 3. 실행 및 연결 확인

Excel을 다시 실행하면 XLAM과 등록된 DLL이 함께 로드됩니다. 별도로 DLL 파일을 더블클릭하지 않습니다.

Excel에서 **파일 → 옵션 → 추가 기능 → 관리: COM 추가 기능 → 이동**을 열어 **내엑셀 NxHost**가 체크돼 있는지 확인하세요. 목록의 체크는 추가 기능 로드 여부를 뜻합니다. DLL 기능이 실제로 연결됐는지는 해당 기능 실행으로 별도 확인해야 합니다.

고도화 배포본의 문서 비교와 아래한글 표·그림 전송은 DLL을 사용합니다. DLL 연결이 안 되면 해당 기능은 실행되지 않습니다. 설치와 비트수를 확인하거나 DLL 없이 작동하는 내부망 단일 XLAM 배포본을 사용하세요. 다른 기능의 기존 대체 경로는 유지됩니다.

r105 고도화 배포본은 DLL 서비스를 연결할 때 설치된 파일을 배포 당시의 SHA-256과 대조합니다. 파일 누락·변경·버전 혼합 오류가 나면 같은 버전의 전체 패키지로 다시 설치하세요. DLL 한 개만 다른 버전으로 교체하지 마세요. 이 검사는 파일 일치 여부를 확인하며 게시자 전자서명이나 코드 분석 차단을 뜻하지 않습니다.

r105의 NxHost32/64.dll은 보호 로더이며 NxCore32/64.dll이 실제 기능 모듈입니다. 네 파일을 같은 버전으로 함께 설치해야 합니다. 로더가 핵심 모듈을 검사한 뒤 로드합니다. 사용기한은 발급된 정보의 서명으로 확인하며, 기한 만료 또는 보호 정보 오류 시 내엑셀 대분류의 안내·제거 메뉴만 사용할 수 있습니다. 사용기한과 보호장치의 임의 변경은 AI·자동화 도구를 사용한 경우에도 금지됩니다.

## 4. 기존 버전 및 오류

- `EXCEL_RUNNING`: Excel 문서를 저장하고 모든 Excel 창을 종료한 뒤 다시 실행하세요.
- `XLSTART_CONFLICT`, `NXHOST_REGISTRATION_CONFLICT`, `ACTIVE_INSTALL_STATE_CONFLICT`: 기존 내엑셀 설치가 있습니다. 이전 배포본의 제거 절차로 정리한 뒤 새 버전을 설치하세요. 사용자 문서나 다른 추가 기능을 임의로 삭제하지 마세요.
- 스크립트·매크로·DLL이 보안 정책으로 차단되면 오류 내용을 확인하세요. 회사 정책을 임의로 변경하지 말고 허용 여부를 확인해야 합니다.
- NxHost가 목록에 없거나 체크가 유지되지 않으면 설치 출력과 Excel의 비활성 항목을 확인하세요. 리본이 보이는 것만으로 DLL 연동 성공을 판단하지 않습니다.

서명 여부와 설치 후 DLL 검증 범위는 **해당 버전의 출시기록**을 확인하세요. r105은 무서명이며, 설치·COM 등록 후 DLL 기능 수용 검증은 별도입니다.

## 5. 제거

문서를 저장하고 Excel을 모두 종료한 뒤, 설치에 사용한 버전의 `패키지` 폴더에서 실행합니다.

```powershell
powershell.exe -NoProfile -File ".\deployment\Uninstall-NxEnhanced.ps1" -PackageRoot "."
```

설치 패키지는 제거 및 복구에 사용할 수 있도록 보관하세요. 내부망 단일 XLAM 배포본에는 이 DLL 등록 절차를 적용하지 않습니다.
# r105 설치 관리 안내

완전 삭제 성공 화면에서는 ‘마침’으로 종료하거나 ‘초기화면으로 돌아가기’로 설치 첫 화면을 열 수 있습니다. 돌아가기만으로 설치가 시작되지는 않습니다.

2026-09-26 완료 화면 개선: 설치 완료 하단은 ‘상세 로그 보기 · Excel 실행 · 마침’ 순서입니다. Excel은 해당 버튼을 눌렀을 때만 실행되며, 마침은 설치 창만 닫습니다. 완전 삭제가 성공하면 삭제 버튼이 ‘마침’으로 바뀝니다.

2026-09-26 통합 후보: 설치 EXE의 ‘완전 삭제 (설치 이력 포함)’ 버튼으로 초기화 화면을 엽니다. 설치 프로그램은 종료되고 임시 위치에서 초기화를 이어갑니다. 초기화 화면에서 대상을 확인하고 실행하면 백업 없이 삭제합니다. 이후 설치하려면 원래 내려받은 EXE를 다시 실행하세요. 충돌 시 32·64비트 DLL 등록 경로를 화면에 표시합니다.

EXE 설치본의 제어판 이름은 ‘내엑셀’이며 버전은 별도 버전 정보에 표시합니다. 이전 버전이 정상적으로 등록되어 있으면 업데이트로 교체합니다. 설치 기록과 실제 등록이 충돌하는 경우에는 함께 제공한 설치 초기화 도구로 설치 내역을 완전 삭제한 뒤 다시 설치하세요. 초기화는 설치 파일·등록·캐시·설치 백업 이력을 삭제하며 복원할 수 없습니다. 문서·양식·사용자 설정은 보존합니다.

이번 수정본은 사용자 실행 환경에서의 설치·제거 확인을 기다리는 후보입니다. 파일 탐색기에서 직접 실행하고 설치 후 제어판 항목과 Excel 자동 실행을 확인하세요.
